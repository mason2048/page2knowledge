# Page2Knowledge 云运行边界

此目录给出“可构建、可运行、可运维”的生产容器基线，不代表已经部署上线。正式开放前，仍须完成服务端鉴权、网络策略、备份恢复演练和真实业务验收。

## 运行契约

- 镜像使用 Node.js 24 Alpine 多阶段构建，最终镜像不包含 TypeScript、Vite、测试或源码。
- `npm run build` 必须同时生成前端 `dist/` 和服务端 `dist-server/server/index.js`。
- `npm start` 必须先校验生产访问令牌，再运行 `node dist-server/server/index.js`，不得在生产镜像中依赖 `tsx`。
- 服务必须在容器内监听 `0.0.0.0:4315`；宿主机端口只绑定 `127.0.0.1`，由 HTTPS 反向代理接入。
- `/api/health` 用于存活检查。健康响应仅代表进程可达，不代表抓取、持久化或完整业务流程通过。
- `/data` 是唯一持久化写入点。默认知识库与调度状态分别为 `/data/knowledge-store.json`、`/data/scheduler-state.json`。
- 容器以非 root 用户运行、根文件系统只读，删除全部 Linux capabilities，并启用 `no-new-privileges`。

当前服务代码若尚未满足上述监听、编译启动、鉴权或持久化路径契约，镜像只能视为构建候选，不能对外开放。

## 构建与本地静态验收

从产品目录构建固定候选：

```sh
docker build --pull --tag page2knowledge:local .
docker image inspect page2knowledge:local
```

Compose 要求令牌由调用进程环境提供；不要创建或提交 `.env` 文件：

```sh
export PAGE2KNOWLEDGE_ACCESS_TOKEN="$(openssl rand -base64 48)"
docker compose -f compose.yaml config --quiet
docker compose -f compose.yaml build --pull
```

这里不自动启动容器。若获准进行运行验收，再执行 `docker compose -f compose.yaml up -d`，检查健康状态、鉴权失败/成功、持久化重启和反向代理链路，之后使用 `docker compose -f compose.yaml down`；不要附加 `--volumes`，否则会删除持久化数据卷。显式传入 `-f compose.yaml` 可避免旧工具或同目录其他 Compose 文件造成歧义。

## 身份验证与密钥

`PAGE2KNOWLEDGE_ACCESS_TOKEN` 必填，Compose 在变量缺失时拒绝解析，容器的 `npm prestart` 与应用启动都会在去除首尾空白后按 UTF-8 字节数校验，少于 32 字节时拒绝启动。生产平台应从托管密钥服务把随机令牌注入为环境变量；不得写入镜像层、Compose 文件、源码、日志或备份说明。内部空白不会被删除，令牌发送值必须与去除首尾空白后的配置值完全一致。

除 `/api/health` 外，所有数据 API 都要求：

```text
Authorization: Bearer <PAGE2KNOWLEDGE_ACCESS_TOKEN>
```

比较时必须使用恒定时间校验。拒绝把令牌放在 URL、查询参数或 Cookie 中。轮换时先在受控维护窗口替换密钥、滚动重启，再确认旧令牌失效；发生泄漏时立即轮换并检查代理访问日志。容器层的“变量非空”检查不能替代应用层逐请求鉴权。

静态应用外壳可公开加载以便浏览器呈现令牌输入框，但它不包含任何知识数据；令牌只保存在当前浏览器 `sessionStorage`，所有读取、导入、抓取、检索、问答与调度请求仍必须通过上述鉴权。若组织政策要求连静态资源也不可公开，应由反向代理在应用前增加独立的身份认证层。

## HTTPS 反向代理

公网流量必须先经过受维护的负载均衡器或反向代理：

1. 仅开放 TCP 443；HTTP 80 只用于跳转到 HTTPS。
2. 使用可信 CA 证书和自动续期，最低 TLS 1.2，启用 HSTS、合理请求体上限和请求超时。
3. 上游指向宿主机 `127.0.0.1:4315` 或同一私有容器网络，绝不直接发布容器端口到公网。
4. 保留原始请求 ID，但不要记录 Authorization、上传正文、抓取正文或导出的知识内容。
5. 代理必须转发 `Authorization`；健康检查应直接访问 `/api/health`，不能把其他路径加入免鉴权列表。
6. 若跨域部署前端，只允许明确列出的源、方法和请求头；不要使用通配 CORS。
7. 应用不信任 `Forwarded` 或 `X-Forwarded-*`。HTTPS 代理必须保留外部 `Host`，并同时配置精确的 Host 与浏览器 Origin。若代理传入 `Host: knowledge.example`，配置 `PAGE2KNOWLEDGE_ALLOWED_HOSTS=knowledge.example` 和 `PAGE2KNOWLEDGE_ALLOWED_ORIGINS=https://knowledge.example`；若代理确实保留 `:443`，Host 配置也须包含该端口。Origin 的显式默认端口 `:443`/`:80` 与省略形式等价。不支持通配符或多值请求头；真正跨域部署需另行增加独立且可审计的 CORS 设计。

上传限制应同时在代理和应用层执行，并以更小的一方为准。应用在上传流进入内存时按 PDF 20 MiB、转录 5 MiB、音视频 250 MiB 分别截断，并默认只允许一个高开销上传/解析/爬取任务；代理仍应施加同等或更严的总请求体、请求并发和速率限制。代理超时需要覆盖受支持的 PDF 解析时长，但不得允许无限请求。

## SSRF 与出站网络

应用已有 URL、DNS、重定向和地址分类校验，但生产必须再用网络层执行拒绝策略。攻击者可利用 DNS 变化、代理差异或解析器缺陷绕过单层校验。

- 抓取工作负载放入独立子网或网络策略；默认拒绝出站，再仅允许 DNS 到受控解析器及 HTTP/HTTPS 到公网目的地。
- 明确阻断 RFC1918 私网、环回、链路本地、保留/文档网段、IPv4-mapped IPv6、ULA，以及云元数据地址 `169.254.169.254` 和云厂商元数据域名。
- 禁止访问控制面、数据库、缓存、对象存储私有端点和集群 service/pod CIDR。
- 更严格的环境应使用只允许公网目的地址的受审计出站代理；代理需重新解析并校验每次重定向，限制端口为 80/443，且不得携带入站 Authorization。
- Compose 的默认 bridge 网络不能完整表达这些目的地址规则，只适合单机候选验证。生产需用云防火墙、Kubernetes NetworkPolicy 加 CNI/FQDN 策略，或专用 egress gateway 实现。

每次网络策略变更后都要测试：公开页面成功；localhost、私网 IP、云元数据、DNS rebinding 和向私网重定向均失败。

## 数据、备份与恢复

`page2knowledge-data` 卷可能包含页面正文、来源、用户上传的本地文件派生内容、索引和调度记录，应按业务数据保护，而不是当作缓存。

- 对底层加密卷做每日快照，并保留至少一份异账号或异区域副本；具体 RPO/RTO 由数据负责人批准。
- 备份前暂停写入或使用存储层一致性快照。本地 JSON 文件不能在复制到一半时作为有效备份。
- 备份应加密、最小权限访问、设置生命周期和审计；禁止把访问令牌混入备份。
- 恢复时先在隔离环境校验 JSON 可读、文件所有者为容器 UID/GID `1000:1000`、权限不宽于 `0600`，再切换服务。
- 至少每季度完成一次从备份恢复、检索、引用定位和调度状态检查。只有真实恢复成功才能证明备份有效。

直接复制 Docker 命名卷前，应停止单个写入实例。销毁环境时先确认备份和保留策略；`docker compose down --volumes` 会不可恢复地删除本机数据卷。

## 日志与监控

应用日志写到 stdout/stderr，由平台采集。Compose 仅提供单机日志轮换上限，生产应转发到具备访问控制和保留周期的日志服务。

- 记录时间、级别、请求 ID、路由、状态、耗时、结果计数和脱敏错误码。
- 不记录 Authorization、Cookie、请求/响应正文、上传文件内容、完整知识块、访问令牌或 URL 中意外携带的凭据。
- 对重复鉴权失败、SSRF 拦截、抓取失败率、5xx、延迟、内存、卷空间、健康检查和调度连续失败告警。
- 健康检查日志需采样，避免淹没有效事件。所有错误信息继续执行密钥遮蔽。

## 容量与扩容

当前 `/data` JSON 存储和进程内调度是单写者模型，生产最多运行一个有状态副本。不要让多个副本并发挂载并写同一文件或普通 NFS 卷。

扩容分为两个阶段：

1. 单副本阶段通过 CPU/内存纵向扩容，并维持 768 MiB 起始内存、1 CPU、128 PID 的基线；依据最大受支持 PDF 的压测结果调整，而不是移除上限。
2. 多副本前，把知识索引迁移到受管理、加密且有备份的向量/文档数据库，把原始对象放入对象存储，把调度迁移到具备租约和幂等性的队列/调度器。迁移完成并验证前，不能宣称水平扩容安全。

定时任务必须由唯一调度者领取；抓取操作应有幂等键、并发上限、指数退避和全局速率限制。扩容不会放宽 robots、版权、来源引用、用户确认或 SSRF 边界。

## 上线门禁

正式发布前逐项留存证据：

- 固定镜像摘要，完成依赖与镜像漏洞扫描，无高危未处置问题。
- 非 root、只读文件系统、capabilities、资源限制和 `/data` 权限在真实平台生效。
- 无令牌、错误令牌拒绝；正确令牌成功；健康端点只暴露最低信息。
- HTTPS、证书续期、HSTS、上传限制、超时和日志脱敏通过。
- SSRF 应用测试与网络层负向测试通过。
- 重启持久化、备份恢复、磁盘满、下游超时和调度失败演练通过。
- 经身份验证的提取、导出、检索、问答、版本比较和用户确认后的定时抓取业务链路通过。

镜像构建成功、容器健康或 HTTP 200 都不是生产业务验收，也不构成已经上线。
